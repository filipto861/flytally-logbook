## 3. Proposed account/event coordination contract for next test-only milestone (NOT FROZEN DDL)

1. **DB-owned identity:** `(owner_user_id, event_kind, event_uid)` unique, immutable and stable across Edit/Certify/Correction/Trash/void. This is distinct from installation-local parent row `id`, human `flightFingerprint`, and signed issuer/account continuity. `event_kind` must be typed; no default `NULL` or synthetic issuer.
2. **Lifecycle reservation:** an account-scoped registry row must persist through active/Trash/void to prevent UID resurrection, with **one legal state at a time**. A parent may have a nullable staged UID on legacy rows until explicit backfill, but restoring from a backup without proven UID and trusted source must be **UNAVAILABLE**. The registry/parent ownership and immutable UID need DB-enforced constraints, not only app `SELECT` checks.
3. **First-lock rule for cooperating writers:** acquire all affected account-event rows in a separate first transaction statement **before** parent/child row locks and before reading mutation predicates. Acquire multiple account IDs in ascending order; independently verify cross-user owner relationship. Re-read event, old/new parent, children and current certification/Trash/void after the lock, in later SQL statements with tested `READ COMMITTED` semantics. Preserve current existing advisory locks until each flow is explicitly reconciled, rather than changing them in a bulk refactor.
4. **Noncooperating writer protection:** a DB UNIQUE identity (plus owner-bound FKs, immutable UID and legal-state constraints) must reject duplicate live identities even if an ordinary write uses no advisory lock. **A row-trigger acquisition is a defensive last resort, not proof of first-lock ordering or fresh snapshots**. Test normal draft Edit/FSTD/Trash/void at SQL level, not just a synthetic parent table.
5. **Cross-user evidence** (`source_user_id` / `participant_user_id`, signer, instructor, PIC link) is not a license to acquire another pilot's user gate without a tested sorted lock set. A verified source/participant event link is **not** one globally shared regulatory record; the recipient keeps independent evidence.
6. **Retention policy is a blocker:** after 90-day `deleted_flights` purge or account privacy erase, what minimal non-PII identity claim can remain and for how long? No indefinite personally identifying retention without explicit product/legal decision. Until frozen, stop an imported event whose prior state cannot be proven rather than guess.
7. **Do not wire V22 into `lib/migration-plan.ts`, `ensureRuntimeSchema`, `db-optimization`, or production routes** during test-only stage. Isolated schema objects under a separate random `ft_m0b_*` schema with real PG16 two-session tests only. Ensure test and production DB targets cannot be confused. Actual Neon HTTP parity is separately required prior to runtime adoption.
