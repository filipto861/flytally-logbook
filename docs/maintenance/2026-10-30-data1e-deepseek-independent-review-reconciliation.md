### Material refinements to reviewer recommendations

1. **D1 HMAC:** the gap is authenticity of the *enclosing stored archive*, not complete absence of certification/record validation. Whether DB is a trusted persistence boundary is a policy question, but storing a signed v13 without verifying its signature on restore is unjustified without a documented compensating control.
2. **D2 150 MiB expanded:** the uploaded-file size limit and the same numeric decompressed limit should not be conflated. A cap must also cover allocations for Base64, compressed bytes, UTF-8 JSON, parse object, GET response, in-memory concurrency and legacy compatibility. Recommend owner freeze limits **after** source-backed valid archive-size inventory and bounded memory assessment, not as an invented provider limit.
3. **D4 TOCTOU:** moving preflight into a transaction is not by itself enough unless execution's actual rows/locks/ownership are tied to that check; a dynamic transaction approach may require changes to the SQL adapter. Protect **FSTD as well as flights**, plus all protected child/audit rows. A pure 'return count' patch cannot fix potential overwrite.
4. **F4:** session calls can update last-seen as well as trigger schema ensures; do not label unauthenticated no-cookie GET as a database-write test without measuring its actual branch. Use exact authenticated local fixtures.
5. DeepSeek's source excerpt package did not include certain files. Reconciliation independently fetched the files listed above, but no tests, real payloads, unknown production settings or third-party raw-source ZIP integrity were verified. Keep **UNVERIFIED/NOT RUN** ledger unchanged.
