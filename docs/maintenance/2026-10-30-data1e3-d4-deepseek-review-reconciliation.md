## 3. Important corrections / nuance in using the review

1. **Option A parent strict INSERT is a partial mitigation, not complete D4 approval.** It prevents the specifically reproduced same-ID conflict-then-update path by raising a SQL constraint error before the UPDATE; do not assume a subsequent UPDATE is safe on its own. A small A1 batch is sensible for testing, but cannot be declared D4 PASS while F9 broad delete and other protected child skips exist.
2. **Natural key:** `flights` restore index currently **not unique**. The six-field business identity may collide for legitimate manually recorded segments; do **not** auto-add `UNIQUE` without owner product decision and migration compatibility audit. Advisory lock parity is necessary for cooperating Create/Restore/Trash workflows, but cannot alone guarantee uniqueness across all writers. Require an execution-time within-transaction recheck *and* independently confirm missing noncooperating paths; if unsure fail closed on ambiguous exact restore rather than claim global database guarantee.
3. **Real triggers:** source `logbook_protect_locked_flight` and `logbook_protect_certified_fstd` protects already-certified/locked records; active runtime effectivity not checked. Minimal synthetic tests without triggers should not be upgraded to a certified production exploit. Audit source is unquestionably broad, but canonical live audit policy/ID collision remains untested.
4. **Audit policy decisions not yet approved.** Default preservation of all independent audit rows is a nonnegotiable invariant, but how to represent restore-generated transient trigger events versus archived audit remains *OPEN*. A policy using broad delete, blanket trigger disable, txid thresholds or synthetic backdating cannot be inferred from reviewer suggestions.
5. **Counts:** CTE query is a reasonable approach; check CTE parser/adapter and SQL budget and reporting for settings, profile and legacy. Count "actual committed inserts" must not include failed/rolled-back writes; clarify whether profile update counts as a restored record.
6. **Safety backup:** do not equate main transaction rollback with no side effects across the whole restore request. Separate pre_restore snapshot may persist.
7. **Release order:** archive D2 compressed/decoded bound still not frozen or implemented; signed-v13 application HTTP/restore, real two-session canonical SQL and browser/release candidate evidence still NOT RUN.
