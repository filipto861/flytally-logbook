## Mandatory frozen acceptance before implementation (all **NOT RUN**)

1. Two genuine **signed v13** snapshots with overlapping historical audit records: same exact snapshot repeat is idempotent; different digests with ambiguous issuer/identity **FAIL CLOSED** without duplicate or data loss.
2. Source `flight_id` equals a different destination/current/voided/reused flight ID: **no misattribution**; account and provenance binding preserved; orphan histories visible only through a safe account-scoped path.
3. Same-origin native v14 backup roundtrip, cross-database snapshot, and imported-ledger v14 re-export/re-import: no duplicates without source proof, no removal of genuine trigger events.
4. A valid complete v14 signed safety snapshot includes **both ledgers** in one verified read-only REPEATABLE READ snapshot; parser rejects missing section/count or unknown format version; upgrade `validateAccountBackupSnapshotResults` cardinality contract.
5. Two real PG16 sessions race on same namespace/id identical vs conflicting content and independent native audit insert; verify Neon HTTP fixed array parity, actual committed counts and full rollback.
6. Legacy v5–v12 trust labels and v13 signature failures; prevent any `flag OFF` unsafe fallback. Verify export/storage/recovery caps and schema migration effectivity independently.
7. Restore-generated native audit actor wording is neutral; protected certified history and source/participant evidence stay distinct. No user PII, GPS or secret fixtures.
