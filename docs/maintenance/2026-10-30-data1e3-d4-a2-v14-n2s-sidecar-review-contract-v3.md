## 1. N2-S — proposed sidecar logical model (NOT SQL)

`native_audit_event_identity` records:
- `native_audit_id`: one-to-one reference to local `flight_audit_log.id` with uniqueness/PRIMARY KEY, no change to the native audit row's `id`, `actor_user_id`, `flight_id`, `old_data`, `new_data`, `changed_at` or action.
- `native_user_id`: actual native event owner, enforced by transaction-bound DB lookup/constraint; never infer from incoming archive sourceUserId.
- `event_uid`: independently random immutable UUID assigned once, with DB uniqueness enforcement. Its role is stable identity for a locally originated audit event, NOT independently verifiable physical source or real-world flight evidence.
- `assignment_kind`: `at_event_insert` or `migration_backfill`, explicit and immutable; `assigned_at`: timestamp of assignment, NOT fabricated audit event time.
- Optional versioned `uid_generation_version`, authenticated lineage claim metadata. A copied installation identifier after database cloning is never sufficient for dedupe.
- Account/ID consistency: sidecar must map exactly one existing native audit row and the same actual owner. Reject missing native parent, ownership mismatch, reused source native ID, duplicate UUID and any attempts to change an existing mapping. DB object ownership/grants and ordinary UPDATE/DELETE/ON DELETE CASCADE are disallowed except a future explicitly authorized audited erasure process. The precise foreign-key/on-delete contract needs reviewer scrutiny, especially legacy F9 audit DELETE.

**New events MUST be mapped atomically with their own native insert.** Candidate minimal design: dedicated `AFTER INSERT ON flight_audit_log` trigger inserts exactly one sidecar mapping in the same database transaction, or an equally proven single-statement mechanism. Existing `AFTER INSERT/UPDATE/DELETE ON flights` trigger remains responsible for generating native audit events. The new hook is a *separate proposed trigger on `flight_audit_log`*, and must NOT rewrite the `flights` trigger or original audit row. If mapping insert fails, native insert must fail atomically; never leave successful native audit events whose UUID is silently pending. Check trigger ordering, DDL permissions, pgcrypto/UUID generator availability, duplicate UID, exception propagation and stress/concurrent insert on isolated PG16.

**Historical rows** get one `INSERT ... SELECT` to sidecar with `assignment_kind=migration_backfill` only after preflight/integrity protection and positively identified test target. No `UPDATE` or `DELETE` of `flight_audit_log`; repeat backfill may only skip existing mapping after proving equal data and valid owner, not merely `ON CONFLICT DO NOTHING`. Concurrent native appends during backfill must neither drop nor double-assign UUID. Do not claim retroactive event origin; records mapped after clone divergence remain ambiguous cross-clone. If database cannot prove complete mapping coverage, event identity remains `UNAVAILABLE` and signed v14 provenance-aware writer must fail closed.

**A sidecar preserves the native audit column shape** used by v13 `SELECT *`, unlike adding N2 fields into native rows. It does NOT automatically make v13 restore safe. `lib/account-restore-v6.ts:224,268-269` still has global MAX, audit DELETE and `ON CONFLICT DO NOTHING`; its unsafe path must not be used for A2 import, or when sidecar constraints could turn legacy DELETE into a fatal half-completed action. Preserve genuine destination audit triggers.
