## Owner-approved C2 — exact policy scope (no SQL)

1. **Immutable observations first:** for each positively authenticated signed-v14 snapshot observation of a native event, preserve the independently identified original snapshot digest/version, signed source user, source-event UUID, assignment kind, original native source IDs and event semantics, canonicalization version/hash, timestamp/actor and declared origin/verification tier. Separate signed snapshot observations remain immutable and individually countable even if displayed under one provisional logical event. The signature is evidence of a *whole snapshot claim*, not physical DB uniqueness, nor timeless independent original row-membership proof. Raw original archive storage is not silently authorized.
2. **Exact authenticated replay:** repeating the *identical signed-v14 snapshot digest* and fully equal source event/ownership/identity metadata is `IDENTICAL`; do not create duplicate event or observation. Same digest with discrepant original event contents, canonical hash, assignment metadata or account claims = `CONFLICT`, abort the whole main restore.
3. **Different valid signed-v14 digests + same authenticated signed source user + same N2-S `at_event_insert` UUID + complete exact canonical event and all identity-critical metadata:** retain a **new distinct signed snapshot observation**. A presentation/index projection may group observations as one *provisional logical UID claim* (`observed_again`), **not** as proof of independent DB instance, original source presence now, two separate historical flights, or independent pilot/regulatory credit. Do not replace previous evidence or infer a matching destination flight.
4. **Conflict gates:** same UID with differing canonical event, ownership, action, actor, source flight, time, old/new data, algorithm/scheme/assignment type or unsupported/missing critical metadata ⇒ whole atomic `CONFLICT`. No "last wins", equal-content fuzzy merge, inferred numeric-ID join, weak default UID or `ON CONFLICT DO NOTHING`. Same UID claimed under another source user does not become a shared event; auth/namespace ambiguity is `BLOCK`, not automatic normalization.
5. **Historical `migration_backfill` UUID:** across *different* signed-v14 digests, even exact UID+equal content is `BLOCK/NEEDS REVIEW` unless **new, separately approved strong lineage evidence** exists. No such evidence is approved, so initial release must fail closed. Same exact signed digest + all-equal row can replay idempotently. Two different UUIDs with coincident content or numeric audit/flight ID remain separate; **never fabricate original event-time UID** for restored v13 or historical rows.
6. **Clone/fork:** a physical clone preserves ancestor UUIDs and potentially signing key; matching UID and valid signature alone **do not authenticate original DB instance**. Distinct native post-clone inserts should get independent random UIDs, but this is testable distribution not cryptographic physical attestation. Store lineage as `DECLARED/UNVERIFIED` absent independent evidence; `verified_at_import_only` remains truthful. Unknown/ambiguous clone history cannot be promoted to `VERIFIED`.
7. **Source v13 data remains v13:** a signed-v14 file may carry already imported signed-v13 evidence; preserve its original signed-v13 source user/ID/digest and strict **A** collision rule. Do not reclassify v13 rows as `at_event_insert` v14 natives or use C2 to evade v13 cross-snapshot conflicts.
8. **Tenant and atomicity:** all read/compare/insert operations are authorized to the destination account with authenticated source user and signature, enforced with transactional database constraints for competing simultaneous imports. Any conflict or inability to establish complete evidence/mapping ⇒ rollback entire main restore, leave committed complete `pre_restore` safety backup intact. Feature flag OFF cannot permit an unsafe downgrade; old F9 MAX/delete path cannot be fallback. No import attests certification, recency, real pilot/editor role or independently approved aviation evidence.
