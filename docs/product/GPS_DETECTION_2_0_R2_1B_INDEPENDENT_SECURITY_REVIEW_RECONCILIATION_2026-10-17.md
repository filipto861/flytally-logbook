## 3. Mandatory hard negative gates before any future live-data experiment

1. Substitute an unrelated owner's subject → query returns no rows (and access rejected, without disclosing identity).
2. Missing/expired/revoked authorization → halt **before any raw-point query**.
3. Replay/grant/cookie abuse → reject; ideally no exposed web endpoint at all.
4. Strict read-only DB role denies `INSERT`, `UPDATE`, `DELETE`, schema DDL and stored routines that mutate data.
5. Whole-request audit shows **zero session heartbeat, migration, schema or flight writes**.
6. Owner predicate and same-owner flight join at each query site; shared-flight participation alone is not automatic track-research permission.
7. Full-resolution points preserved; null altitude remains null, true zero remains zero, acquisition/persisted ordering and missing timestamps recorded.
8. Invalid dt/gaps produce no fake stop/touch event; same normalized source for legacy and new comparisons with `preprocessingConfound=NOT_ISOLATED`.
9. Source material and logs never expose routes, airport/registration combos, per-flight timestamps, stable private hashes, cookies or credentials.
10. Workload limits/timeout and small-cohort suppression fail closed; review reidentification beyond mere count threshold.
11. Explicit output audience, access audit, retention schedule and operator decommission/signoff.

These are **proposed future acceptance tests**, not executed checks. If any gate is uncertain, real-track P1 remains **NO-GO**.
