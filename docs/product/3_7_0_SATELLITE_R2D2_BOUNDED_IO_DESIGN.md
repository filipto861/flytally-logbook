## 1. Verified runtime inventory (base HEAD)

- `lib/satellite-map-provider.ts` (61 lines) exports `isImage`, `CACHE_SECONDS = 604800`, and `satelliteTile`. The latter starts World Imagery and Preferred Labels with `Promise.all` of `fetchProviderTile` returning `Response | null`; only after both fetch promises resolve does it validate response headers and read bodies. If base fails it returns `null`. If preferred labels fail it fetches tokenless Reference Labels; if that fails it returns base-only SVG.
- `fetchProviderTile` calls Next-extended `fetch(url, { headers: { Referer, User-Agent }, next: { revalidate: CACHE_SECONDS } })` and catches all network exceptions to `null`. No signal/deadline/response-size checks exist. The helper is independent of auth and Next imports; source fixtures inject `fetchTile`.
- `isImage` currently accepts any successful response with header starting `image/`. `imageDataUrl` uses untrusted declared content type in an SVG data-URL attribute, and fully buffers `response.arrayBuffer()` before Base64. There is neither magic-byte validation nor decoded-byte ceiling nor final-SVG size ceiling.
- `app/api/map-tile/[z]/[x]/[y]/route.ts` validates tile/style, gates authenticated Satellite, missing token and deployment-scoped exact-true upstream disable *before* provider; valid Satellite SVG response is `image/svg+xml` with `private, no-store`, unavailable Satellite is 502/503 with `no-store`/`unavailable`. Public Standard map path is separate and unchanged in this milestone.
- `tests/v370-map-layers.test.ts` currently includes production-provider unit tests with plain textual fake `image/jpeg` and `image/png` bodies (`image-bytes` / `imagery` / `labels`), which MUST change to actual valid image bytes before signature checking can be accepted. `tooling/satellite-http-upstream-fixture.cjs` likewise uses plain marker strings as fake image bodies and the HTTP runner asserts their Base64. Preserve strict 13/0/0 upstream interception and warm-cache isolation, adapt expected fixture data safely.
- `tooling/verify-satellite-http.mjs` requires existing specific R2D.1 branch; any new R2D.2 HTTP fixture MUST be separately branch-scoped and preserve disposable `flytally_satellite_r1_test|flytally_sat_r1|55432` preflight, browser-native Secure/HttpOnly session, remote-socket blocks, fake token and run-specific valid tile coordinates.
- Map control, Flight Story automatic first-tile probe, Story preview/PNG export, and public Standard-only replay are frozen behavior. Satellite requests from Flight Story can occur even with the interactive Satellite map toggle OFF.

**Critical unproven boundary:** Next 16.3.2 is pinned in `package-lock.json` and `next.revalidate` opts individual upstream fetches into framework Data Cache. A userland streaming limit **after** Next fetch resolves does NOT establish an upstream-cache-miss memory or network ceiling; framework fetch may have buffered a full response for caching first. Exact behavior of its cache adapter, response streaming and `AbortSignal` in this deployment must be measured using a running synthetic Next production server. A source-level `getReader()` guard alone is insufficient proof.

## 2. Contract proposed for review (NOT yet frozen)

1. **Scope:** harden only Satellite's three fixed provider tile endpoints; avoid broad auth, public OSM Standard, Story, Leaflet, GPS, DB and Training changes. Note Standard OSM unbounded `arrayBuffer` as an out-of-scope risk, not an R2D.2 regression or a silent extension.
2. **HTTP boundary:** existing validation order, 400 invalid style, 401 unsigned/revoked, 503 missing token or disabled, and 502 unavailable provider remain exactly unchanged. No provider error/token/session leakage in client payload, HTML, logs or headers.
3. **One bounded upstream attempt:** enforce a reviewed **total deadline covering connection, headers and complete decoded response-body read**; ensure failure promptly settles even if response headers arrive but body stalls. Abort underlying request and attempt safe stream cancellation on timeout/rejection/overage; do not await an uncooperative cancel forever. Handle abort signal and exceptions without unhandled rejections or indefinitely pending sibling tasks.
4. **Body limit:** count *actual streamed bytes returned by the Response reader* before concatenation/Base64. A missing, dishonest, negative, overflowing or contradictory `Content-Length` is not sufficient authority. Reject valid over-limit declared lengths early and always enforce observed-byte ceiling. Count decoded bytes rather than assuming raw transport lengths equal body size. Distinguish loss of declared-length trust from protocol errors. **Limits and MIME allowlist undecided.**
5. **Image validation:** recognize only source-confirmed supported raster MIME types; normalize type rather than interpolate raw upstream headers into SVG. Require matching image signatures and nonempty complete payload; reject HTML, SVG/script markup, mismatched declared type/signature, truncated or zero-length responses. Consider additional image-structure validation needed to rule out broken raster payloads; a magic prefix alone is not a full decoder.
6. **Composition:** only successfully validated base imagery can result in Satellite 200. Valid preferred labels overlay; invalid/unavailable preferred labels trigger Reference Labels fallback; invalid/unavailable fallback labels return base-only. Never emit placeholder labels or a partial/invalid base as Satellite. Bound final SVG bytes (base64 amplification included) using a separately justified ceiling.
7. **Concurrent requests:** current `Promise.all` joins both header responses even if base fails. Prefer cancellable concurrent *fetch-and-consume* tasks, with explicit base-failure sibling abort and settled cleanup, but prove there is no new provider call after base failure and no unhandled rejection. Preserve preferred-first, fallback-second labeling; never start fallback when base invalid. Per-instance concurrency caps/global account quotas are NOT included without pressure evidence; reserve for R2D.3.
8. **Caching:** preserve seven-day upstream cache semantics **only if** synthetic production Next verification demonstrates the desired bounded-I/O guarantees and the cache sees validated content. If impossible, present an explicit owner trade-off: (A) leave cache with incomplete hard-memory guarantee (not acceptable to claim full hardening); (B) use controlled uncached/bounded Satellite fetch, increasing potential provider traffic and cost; (C) design a separate bounded validated cache, broader scope. Do not silently set `cache: no-store` or introduce global quota assertions.
9. **API outcomes:** base/required-data failure → `502`, `no-store`, `X-FlyTally-Map-Style: unavailable`, no image. Optional labels failure + valid base → `200` validated base-only SVG. Existing browser requests separate Standard tile; never substitute image into an error response.

## 3. Evidence required before numeric design freeze

- Synthetic local measurements of known-good/large/slow/corrupt data across the exact pinned Next version, including cache miss/hit, repeated requests, aborted reads, client disconnect and concurrent base/labels.
- Hosting constraints documented (request duration, memory, body size, parallelism) for the actual deployment target, not generic estimates.
- Grounded source evidence for expected image MIME formats, maximum legitimate decoded tile size (base+labels) and ordinary/slow request latency. Until obtained, timeout/byte/aggregate/concurrency values remain **UNDECIDED**; do not insert permissive arbitrary constants or quietly disable the feature.
- Explicit owner decision on cache versus proven upper bound and provider traffic/cost; never infer real-world quotas from per-process counts. Real provider testing remains prohibited here without owner approval.

## 4. Implementation plan after review and freeze (small batches)

**R2D.2-A: cache and abort compatibility spike (synthetic, no runtime patch).** Probe exact Next 16.3.2 fetch behavior with a fake provider that emits slow, endless or oversized streaming responses. Record observable upstream start/abort, chunks, cache hit/miss, duration, memory indications and server exit. Ensure fixture cannot reach provider or production DB. Compare cache-enabled versus temporary local-only no-store variant without shipping behavior changes.

**R2D.2-B: standalone bounded image reader.** Pure helper with injected fetch and clock/test seams only where essential; immutable reviewed budget policy and MIME rules; typed success/failure internally (never convert unknown into valid data). Must test before whole-buffer allocation and ensure deadline spans body consumption.

**R2D.2-C: provider composition and cancellation.** Use validated bounded images; preserve base/labels/fallback ordering and generated SVG shape. Add settled sibling cancellation on required base failure; no global quota/refactor of client UX.

**R2D.2-D: synthetic HTTP + full release verification.** Upgrade existing fixtures with real minimal valid PNG/JPEG image bytes and marker-safe assertions (not literal fake content accepted as images). Add slow/hang, malformed header/body/signature, oversized, truncated, failed abort, labels fallback, base-only, warm cache, disabled upstream 0, missing-token 0, auth revocation, token privacy. Run targeted and iteration, synthetic authenticated Next HTTP, then independent ON and OFF risk-release with disposable PG, desktop/mobile Chromium, before engineering closeout. Physical iPad Safari/real HTTPS/provider remains separately NOT VERIFIED.
