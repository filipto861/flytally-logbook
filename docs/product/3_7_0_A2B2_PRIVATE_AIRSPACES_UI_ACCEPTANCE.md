## Design and safety contract
- `installAirspaceMapControl(map, enabled)` is independent of `installSatelliteMapControl`: separate OFF-default `Airspaces` toggle, no global preference, no automatic apply, no replacement of Standard/Satellite, no new Leaflet map instance, no change to center, zoom, route lines, playback, GPS persistence, certified records, audit or recency.
- Mount overlay only after click at a supported app request zoom `z<=14` in existing `flytallyAviation` pane z-index 300; pane has `pointer-events:none`, zero night filter. Underlying basemap z-index 210; route lines/airport markers z-index 450/470 remain clickable. Zoom ceiling 14 is **FlyTally app budget**, NOT openAIP coverage evidence.
- Tiles travel only through same-origin authenticated `/api/airspace-tile/{z}/{x}/{y}`; API key is never bundled, exposed or passed from the client. No caching of user context. Synthetic PNG required in browser tests, no real vendor traffic.
- Show explicit loading and reference-only currentness/coverage disclaimer; retain openAIP attribution while the layer is enabled. Blank/partial transparent rasters DO NOT prove published or current airspace coverage. Any tile error → remove whole layer, mark unavailable and disable further retry until map remount; preserve basemap and pointer interaction. At zoom above 14, remove layer and show an explicit limit state; zooming back does not auto-reactivate it.
- Authenticated consumers: `RouteOverviewMap`, `TracksMap`, private `FlightTrackPlayer`, `GpsImportReviewPlayer`. `FlightTrackPlayer(publicView)` never enables the control, `PublicFlightMap` unchanged. No public Story or export overlay.
- UX: reuse map control primitives/spacings and 44px button sizing, single independent button, dark mode, mobile coarse-pointer behavior, accessible `aria-pressed`, `role=status`; only activate via exact-true separate build-time client flag. Retain Satellite legacy behavior with its own independently controlled flag.
