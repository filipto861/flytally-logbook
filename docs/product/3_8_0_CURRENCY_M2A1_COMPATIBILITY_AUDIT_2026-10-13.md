# Currency #136 — M2-A-1 compatibility audit (13 October 2026)

**Scope:** read-only source inspection of current-main compatibility boundaries during isolated M2-A-0 Draft PR #338. **No v21 migration registration, DB mutation, or currency UI.** Exact targeted M2-A-0 local PostgreSQL 16 evidence on `8a9e03e0`: static 6/6 PASS, real PG 6/6 PASS, TypeScript PASS, disposable cluster shut down. Those tests exercised a small schema and genuine v20 flight protection, **not** full application persistence, portable signed v13 restore or sharing end-to-end.

## Required acceptance before registering or executing migration v21

1. **Actual runtime schema and restore-path census.** Confirm every write and restore path for `rates`, `aircraft`, `flights`, `flight_expenses`; identify JSON record spread, named projection and trigger boundaries. Test v13 signed export, import and exact restore on a disposable database using both old and future v21-shaped records, with and without new columns.
2. **Compatibility contract.** Old backup/version/legacy rows retain absent currency as unknown; do not synthesize CZK, assign inferred ISO minor-unit exponent, rewrite historical money or recertify. Signed protected payload bytes and archived/voided snapshots remain intact, including independent participant copies.
3. **New-money semantics.** Explicit user default applies only to newly authored monetary values, user may override rate currency, and flight records retain their own source-denomination snapshot. Decimal rates use string/NUMERIC exactness; atomic write-path validation rejects wrong ISO scale/code; no mixed-denomination aggregation or FX.
4. **Sharing and Trash.** Independently version new currency-bearing share metadata, reject invalid/partial tuples, and preserve old shares without coerced currency. Exercise deletion/undo, certification correction and permanent void provenance with explicit money metadata.
5. **Release gates.** Run full Node24 suite, isolated full PostgreSQL acceptance, signed v13 backup/restore, browser/production build and verified Vercel→Neon target preflight as required by changed scope. Register v21 only after separate architecture/owner approval, implementation roadmap milestone and rollback barrier.

## Decision
M2-A-0 targeted tests **PASS**. M2-A-1 compatibility audit is **IN PROGRESS**. The existing v21 SQL stays an **unregistered Draft**; no production or generic source-current guarantee follows from this narrow audit. Sharing and legacy billing numeric coercion are specifically flagged for M3 and must not be replaced by guess-based conversions.
